# Interview Guide

## Project summary

I built an end-to-end fuel-consumption and emissions analytics project using Python,
MySQL, scikit-learn, Streamlit, and Plotly. The workflow cleans 29 model years of
vehicle ratings, creates a relational reporting layer, compares regression models
with a future-year holdout, and serves the results through a MySQL-backed dashboard.

## Decisions worth explaining

- I removed only three exact duplicate rows and retained plausible statistical extremes.
- I kept historical missing CO₂ and smog ratings as null instead of backfilling them.
- I used a temporal split instead of a random split to test performance on newer model years.
- I excluded measured fuel-consumption fields from the primary model to prevent target circularity.
- I used class-year P25 as a screening benchmark, not as guaranteed emissions savings.
- I made the pipeline fail when MySQL is unavailable so the database layer cannot be bypassed.

## Evidence to show

- the `PASS` validation report;
- candidate and test metrics generated by the run;
- MySQL schema and reporting views;
- model feature importance and segment errors;
- all four Streamlit dashboard pages.

Do not claim causal effects, actual fleet savings, real-world emissions, or production readiness.
